# ChatBox

> 给《命令与征服：尤里的复仇》1.001 的**消息历史**插件 ——
> 把刷屏的左上角消息变成现代聊天框，并把每一条都完整记录下来。

一个 [Syringe](https://github.com/CnCNet/Syringe) 插件。**只需自己安装**，
联机时对手不需要装。不依赖 Ares。

---

## 它解决什么问题

原版把所有文本消息挤在左上角，最多 14 条，超出就挤掉最旧的，而且到时间就消失：

- **快捷键提示会淹没一切**。按一次 T（选中同类型单位）就产生一条"选取部队横越地图"，
  一局下来几十条，真正要看的聊天和剧情字幕被冲得没影。
- **过去就查不到**。消息消失后无法回看，想确认"刚才谁说了什么"只能凭记忆。
- **没有来源区分**。系统提示、剧情字幕、玩家发言全都一个样。

ChatBox 做三件事：

| | |
|---|---|
| **完整记录** | 所有消息写进日志文件，一条一行带时间戳，随时可查 |
| **重新显示** | 用聊天框风格的消息框替代原版列表：新消息在下、可展开翻历史、按玩家着色 |
| **分流过滤** | 操作提示类消息不进消息框，不再淹没真正的内容 |

## 主要功能

### 完整捕获所有消息

钩住引擎里**所有文本消息的唯一入口**（`MessageListClass::AddMessage`），
所以玩家聊天、剧情字幕、任务提示、系统通知、快捷键提示**全都能拿到**。

> 作为对比：Phobos 的消息栏只在某一个调用点截获，实测一局 56 条消息里
> 它那条路只能覆盖其中 12 条（仅触发器文本）。

### 日志落盘

- 实时写入 `<游戏目录>\MsgLog\YYYY-MM-DD_HH-MM-SS.log`，每个进程启动一份
- **两种详细程度**由 `LogRaw` 控制 —— 默认只记人能直接看的内容：

  ```
  [09-20 22:15:03] #12 moonbamboo: test
  [09-20 22:15:04] #13 难度： 终结
  ```

  需要排查时打开 `LogRaw=1`，会额外记录调用者返回地址、颜色方案索引、
  超时帧数等内部字段
- 编码可选 GBK（记事本直接看）或 UTF-8（带 BOM）
- 文本里的换行会转义成 `\n`，**保证一条消息一行**，方便 grep

### 消息框

- 半透明底板，新消息出现在**最下面**，旧的往上顶（同现代聊天框）
- **按来源着色**：玩家聊天用**发言者自己**的颜色（与原版一致），
  系统/剧情消息默认用消息自带颜色（可配置成用当前玩家的颜色）
- **长消息自动折行**（用引擎自己的折行函数，所以换行位置和原版一致）
- **折叠态 / 展开态**：平时只显示最新 8 行，展开后显示 15 行并可翻历史
- 折叠态下旧消息会随时间消失（≈原版观感）；**展开态忽略超时**，历史完整可查

### 交互

| 操作 | 效果 |
|---|---|
| **左键点消息框** / `Ctrl+M` | 折叠 ⇄ 展开 |
| **展开时点框外** | 收起 |
| **鼠标滚轮**（悬停框上） | 上滚翻历史（自动展开）、下滚回到最新 |
| `↑` / `↓` | 滚动一行 |
| `PageUp` / `PageDown` | 翻页（步长可配，默认 5 行） |
| `Home` / `End` | 跳到最旧的一屏 / 回到最新 |

- **滚动条**贴在消息框右侧，指示当前翻到哪个位置
- **向上翻历史时冻结自动滚动** —— 新消息到达不会把你正在看的内容顶走

### 过滤操作提示

实测发现 `AddMessage` 的第 7 个参数其实是 **`silent`** 标志：所有"操作提示类"
消息（快捷键提示、路径点提示）都是 `silent=1`，所有"真消息"都是 `silent=0`，
**零例外**。所以用一个判断就能干净分流：

- 默认 `FilterSilent=1` → 操作提示**不进消息框**
- 但它们**照常写进日志**，什么都没丢

## 安装

1. 确保游戏通过 **Syringe** 启动（CnCNet 客户端已内置；独立版见
   [CnCNet/Syringe](https://github.com/CnCNet/Syringe)）
2. 把这三个文件放进**游戏根目录**（`gamemd.exe` 所在目录）：

   ```
   ChatBox.dll
   ChatBox.dll.inj      ← 钩子声明，文件名必须与 DLL 完全对应
   ChatBox.ini          ← 配置，可选（缺失则全用默认值）
   ```

3. 启动游戏。Syringe 日志里应出现：

   ```
   Recognized DLL: "ChatBox.dll"
   ...
   ```

   与 NoCopyProtect / AutoLoad / AutoKit 共存时钩子总数为 15。

> **纯原版 gamemd.exe 带有防拷保护**，直接运行会静默退出。若你的环境没有
> CnCNet 客户端，可能需要先解决这个问题（本项目作者另有一个 `NoCopyProtect`
> 插件专门处理）。

## 配置

全部选项都在 `ChatBox.ini` 里，文件内有详细中文注释。常用几项：

| 项 | 默认 | 说明 |
|---|---|---|
| `ChatBox` | `1` | 总开关 |
| `ShowWindow` | `1` | `0` = 完全不碰画面（纯日志模式） |
| `MaxLines` | `8` | 折叠态显示几行 |
| `ExpandLines` | `15` | 展开态显示几行 |
| `ScrollStep` | `5` | 翻页/滚轮一次滚几行 |
| `FilterSilent` | `1` | 操作提示不进消息框 |
| `MaxWidth` | `0` | 消息框宽度，`0` = 自动（屏幕一半） |
| `TopGapLines` | `1` | 顶部预留几行空档（给回车输入框让位） |
| `BoardOpacity` | `45` | 底板不透明度 |
| `SysUseMyColor` | `0` | `1` = 系统消息改用当前玩家的颜色 |
| `LogRaw` | `0` | `1` = 日志记录全部内部字段 |
| `LogUtf8` | `0` | `1` = 日志用 UTF-8（默认 GBK） |

**改动后需重启游戏**（配置只在插件加载时读一次）。

## 兼容性

| | |
|---|---|
| **Ares** | ✅ **完全兼容** —— Ares 没有钩本插件使用的任何地址 |
| **Phobos** | ✅ **可共存** —— 有 3 个地址重叠，但 Syringe 对 `return 0` 的钩子做链式调用，两者都能生效。唯一注意：Phobos 若开启 `MessageDisplayInCenter=1`，会绕开原版消息入口，本插件将漏掉触发器类文本（该选项默认关闭） |
| **其他 Syringe 插件** | ✅ 只要不同时钩住同一地址并返回跳转即可 |
| **联机** | ✅ **只需自己安装**。插件不下发任何事件、不修改任何游戏状态，只读内存 + 读输入 + 画本地屏幕 |

原理：lockstep 同步的是**指令序列**，不是鼠标位置或画面内容。
各客户端的消息框内容可以完全不同（就像分辨率设置不同一样），不影响同步。

## 从源码构建

需要 **32 位 mingw**（作者用 w64devkit-i686-1.23.0 / GCC 14.1.0）：

```bat
g++ -O2 -shared -fno-exceptions -fno-rtti -o ChatBox.dll ChatBox.cpp ^
    -nostdlib -lkernel32 -luser32 -lgcc ^
    -Wl,--enable-stdcall-fixup -Wl,--no-insert-timestamp -Wl,--entry,_DllMain@12
```

或直接运行 `src/build.bat`（会自动处理中文路径问题）。

> ⚠️ **工具链必须放在纯 ASCII 路径下**，否则 32 位 gcc 用 ANSI API 取自身路径时
> 会丢字符，报出莫名的 `ld.exe: cannot find -lkernel32`。

代码是 **C++ 受限子集**：不用 STL、不用异常/RTTI、不用全局对象，
全程只用函数指针与 POD 结构，因此**不依赖 CRT**。

## 已知限制

- **只做了折叠/展开两态**，没有独立的"隐藏"状态
- **滚动条只是指示器**，不支持鼠标拖动
- 单条消息超过 512 字符会被截断
- 内存历史固定 200 条（磁盘日志不设上限）
- 绘制接管是**替换**原版消息列表 —— 装了本插件就看不到原版的左上角消息了
  （这是刻意的，否则同一条消息会显示两遍）
